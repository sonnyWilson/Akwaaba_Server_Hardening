\section{Project Status Update}

Since the start of the semester, the team has successfully deployed, analyzed, and configured the Akwaaba Steakhouse server virtual machine environment on Red Hat Enterprise Linux (RHEL 8.4) \cite{VMConnect, AkwaabaConfig}. The team completed the baseline architectural analysis of the web application stack (Apache HTTP Server 2.4.37, MariaDB 10.6.4, and WordPress CMS), establishing GlobalProtect VPN remote administration access and verifying system user roles across the corporate HQ and store locations \cite{VMConnect, AkwaabaConfig}. Based on our preliminary discoveries, minor adjustments were made to the initial milestone schedule: task deadlines for technical file system hardening and ACL drafting were aligned directly with the NIST SP 800-30 Rev. 1 guidelines \cite{Phase1Guide, RiskGuide}.

From a project management perspective, minor initial hurdles were encountered regarding remote database access. These issues were resolved through team coordination by conducting meetings and standardizing access methods. Communication and workflow across team members remain on schedule, and all Phase 1 deliverables including the Information Security Policy, Access Management Matrix, and Server Risk Assessment have been finalized in full compliance with course milestones and industry standards \cite{Phase1Guide, LiISP, RiskGuide}.

\section{Phase 1 Solution Report}

\subsection{Information Security Policy for Akwaaba Steakhouse}

\subsubsection{General Security Policy}
Akwaaba Steakhouse operates two dining locations (NYC, Atlanta, LA) and corporate headquarters, employing $\sim$60 personnel \cite{AkwaabaConfig}. This policy enforces administrative and technical controls to preserve the Confidentiality, Integrity, and Availability (CIA Triad) of Akwaaba's e-commerce platform and store operations \cite{AkwaabaConfig, LiISP}.

\begin{itemize}[leftmargin=*]
    \item \textbf{Internet Access \& Network Use Policy:} Corporate networks and POS terminals are strictly reserved for authorized business processing; personal web browsing, streaming, and unauthorized software downloads are prohibited \cite{Phase1Guide, LiISP}. POS terminals and database subnets are logically isolated from guest Wi-Fi via firewalls and VLANs \cite{AkwaabaConfig, Phase1Guide}. Direct public SSH (Port 22) or DB access is banned; remote access requires an authenticated GlobalProtect VPN session (\texttt{vpn.kennesaw.edu}) with Multi-Factor Authentication (MFA) enabled \cite{VMConnect, Phase1Guide}.
    \item \textbf{Email \& Electronic Communication Policy:} All corporate scheduling, customer communications, and financial correspondence must utilize company-issued email accounts \cite{Phase1Guide, LiISP}. Email gateways enforce anti-phishing, DKIM, and SPF protocols; staff are strictly forbidden from opening unverified attachments \cite{Phase1Guide, LiISP}. Transmitting primary account numbers (PAN) or unencrypted employee PII over email is strictly prohibited \cite{Phase1Guide, LiISP}.
    \item \textbf{Bring Your Own Device (BYOD) Policy:} Personal employee devices are strictly banned from connecting to internal POS networks or backend database subnets \cite{AkwaabaConfig, Phase1Guide}. Corporate access on personal mobile devices (HQ staff only) requires registration in Enterprise Mobile Device Management (MDM) with mandatory full-disk encryption and remote wipe capabilities \cite{Phase1Guide}.
    \item \textbf{Password \& Authentication Controls:} All passwords must be at least 14 characters, combine uppercase, lowercase, numeric, and special symbols, and rotate every 90 days \cite{Phase1Guide}. Default administrative passwords (e.g., initial MariaDB passwords) must be changed immediately upon installation \cite{AkwaabaConfig, Phase1Guide}. Accounts lock for 30 minutes after 5 failed login attempts \cite{Phase1Guide}.
\end{itemize}

\subsubsection{Access Management Policy}
Akwaaba enforces Role-Based Access Control (RBAC) and Least Privilege principles \cite{Phase1Guide, LiISP}. System permissions strictly correspond to job function, governed by the Bell-LaPadula confidentiality model (Simple Security: \textit{No Read Up}; $\star$-Property: \textit{No Write Down}) \cite{LiISP}.

\subsubsection{Technical System Hardening \& ACL Implementation}
POSIX permissions and Linux File System Access Control Lists (ACLs) enforce strict boundary isolation on the RHEL 8.4 server \cite{AkwaabaConfig, LiISP}:
\begin{enumerate}[leftmargin=*]
    \item \textbf{Web Root Hardening (\texttt{/var/www/html/home}):} Ownership set to \texttt{apache:apache} with directory permissions \texttt{750} (\texttt{rwxr-x---}) and file permissions \texttt{640} (\texttt{rw-r-----}) \cite{AkwaabaConfig, LiISP}.
    \item \textbf{WordPress Configuration (\texttt{wp-config.php}):} Permissions restricted to \texttt{600} (\texttt{rw-------}) owned by \texttt{apache:apache} \cite{AkwaabaConfig, LiISP}.
    \item \textbf{PHP-FPM Process Isolation (\texttt{/etc/php-fpm.d/www.conf}):} Execution restricted via \texttt{listen.acl\_users = apache} \cite{AkwaabaConfig}.
    \item \textbf{Granular Developer ACLs:} Enforced via POSIX ACL: \texttt{sudo setfacl -R -m u:webdev:rwx /var/www/html/home} \cite{LiISP}.
\end{enumerate}

\subsection{Risk Assessment on the Akwaaba Server}

\subsubsection{Overall Evaluation of Server Infrastructure}
Akwaaba Steakhouse operates a centralized e-commerce and operational server environment hosted on RHEL 8.4 \cite{AkwaabaConfig}. The technical stack consists of Apache HTTP Server 2.4.37, MariaDB Database 10.6.4, and a WordPress CMS instance (\texttt{/var/www/html/home}) supporting web e-commerce operations and multi-location dining services \cite{AkwaabaConfig}. Remote administration is conducted via SSH (Port 22) restricted through a GlobalProtect VPN gateway (\texttt{vpn.kennesaw.edu}) \cite{VMConnect}. Baseline security evaluation reveals initial configuration exposures in \texttt{wp-config.php}, overly broad default PHP-FPM execution permissions (\texttt{listen.acl\_users = apache, nginx}), and administrative backend login portals (\texttt{/wp-admin}) relying on static default credentials (\texttt{Kennesaw123!}) lacking MFA and rate-limiting \cite{AkwaabaConfig, RiskSlides}.

\subsubsection{Important Assets to Protect}
In accordance with NIST SP 800-30 Rev. 1, enterprise assets are categorized into Digital and People assets \cite{AkwaabaConfig, RiskGuide}:
\begin{itemize}[leftmargin=*]
    \item \textbf{Digital Assets:} Customer Payment \& Transaction Data (MariaDB database tables, payment logs); E-Commerce Application Platform (WordPress web files, site configurations, Apache server); Server Operating System \& Infrastructure (RHEL 8.4 host, system root, SSH service, PHP-FPM engine); Corporate Financial \& HR Records (general ledgers, payroll profiles, employee PII) \cite{AkwaabaConfig}.
    \item \textbf{People Assets:} Corporate Administrative Staff (1 Owner, 1 Chief Accountant, 2 HR Agents, 1 Web Developer); Store Operational Personnel ($\sim$50 store staff including General Managers, Waiters, Hosts, Bartenders, and Kitchen Cooks) \cite{AkwaabaConfig}.
\end{itemize}
